# Pipeline Decision Proposal

Draft in chat; a status label is not approval. Reuse a current agreement if its
scope and independent consent cover the same candidate work. Persist only after
content/destination permission; ADR only for durable non-obvious trade-offs.

- Outcome, mode and capability boundary; exclusions.
- Repository/source snapshot and exact affected files.
- Events, branches/tags, trusted revision and untrusted contributor policy.
- Stages: command/interface, provenance/version, inputs, runner and outputs.
- Artifact: immutable identity, publication destination, overwrite control, provenance.
- Requested environments: entry criteria, authorized deploy/verify/rollback interface.
- Production: approver identity/policy, environment permission, stale/concurrent work.
- Credential references: type, least-privilege scope and trust boundary, never values.
- Provider capabilities: actual tool/version, available validation and gaps.
- Checks: exact snapshot, allowed effects, acceptance conditions and unavailable proof.
- Remote envelope if requested, independently authorized; no implicit trigger.

Repair: supported causal error and bounded correction/validation. Modernization:
preserved behavior and explicitly approved deviations. Supersede a changed durable
ADR with a new record rather than rewriting its historical evidence.
